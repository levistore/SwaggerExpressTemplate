Tiga langkah yang sama di semua bahasa. Pilih tab sesuai alat lu.

Auth

POST /api/auth/register publik

Daftar akun baru. Balikannya langsung token, jadi nggak perlu login terpisah sesudah daftar. Password di-hash scrypt sebelum disimpan.

Request body 
{
  "name": "Levi",
  "email": "levi@contoh.com",
  "password": "rahasia12345"
}
Respons · 201 Created 
{
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.…",
  "tokenType": "Bearer",
  "expiresIn": "7d",
  "user": {
    "id": 52,
    "name": "Levi",
    "email": "levi@contoh.com"
  }
}

POST /api/users bearer

Bikin user langsung, tanpa lewat alur register. password opsional: boleh nggak dikirim sama sekali, tapi kalau dikirim wajib minimal 8 karakter. Responsnya nambahin hasPassword.

  "name": "Levi",
  "email": "levi@contoh.com"
}
Respons · 201 Created 
{
  "id": 53,
  "name": "Levi",
  "email": "levi@contoh.com",
  "hasPassword": false

Semua bentuk kegagalan

Pesan di bawah ini disalin apa adanya dari respons API, termasuk satu kasus yang balas HTML alih-alih JSON.

Catatan jujur

Yang perlu lu tahu sebelum pakai

PUT bukan update sebagian. Kirim name dan email dua-duanya. Kalau salah satu nggak ada, API balas 400 — bukan menahan field yang lama.
Belum ada cek kepemilikan. PUT dan DELETE /api/users/:id cuma butuh token yang valid, bukan token milik user yang bersangkutan. Selama belum dibatasi, jangan pakai buat data yang sensitif.
GET /api/users terbuka dan memuat email. Tanpa token, siapa pun bisa membaca daftar user beserta emailnya. Sengaja dibiarkan begini biar enak dipelajari, tapi ini yang pertama harus ditutup kalau dipakai sungguhan.
JSON yang rusak dibalas HTML. Kalau body request bukan JSON valid, Express balas halaman error HTML bawaan dengan status 400 — jadi jangan asal res.json() tanpa cek header Content-Type.
